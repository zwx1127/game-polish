# game-polish skill：基于真实轮次的能力补齐

## 核查范围

对照上一轮标题 UI 与主角起步动画实跑，用户后续要求是动画一致性/连贯性、风格统一、每轮效果和报告、回归与回退。本次仅修订云端 workflow skill 和相关开发文档，不修改 llm-game、Windows 源工程、模型运行时或调度器，不推送。

## 确认缺口与改动

1. **动画验收过于泛化。** 原指南要求截图/视频，但没有起步、停走、循环接点、左右脚、受影响方向和长帧/整圈边界。上一轮独立审查实际发现取模掩盖整圈进度的错误。新增按需 `references/animation-and-assets.md`，要求对应问题的连续帧与实际游戏场景验证，禁止用静态标题图替代动画请求。
2. **素材集成与风格保存缺少具体检验。** 新指南要求确认实际加载的原生/烘焙资源，保留原素材/未改区域，记录生成命令和版本，验证二进制正反补丁。不是强制重绘、重新生成全部角色或重建素材目录。
3. **命令成功与测试成功混淆风险。** 实跑出现 gdx `test.run` 外层 ok:true、内层 result.result.ok:false。收尾指南明确检查内层测试结果/count/failures，并指出现有 CLI expect_json_ok 只检查顶层，不能代替测试语义审阅。
4. **源文件副作用与回退范围不足。** 编辑器可规范化 project.godot/import 侧文件，评审场景会写 trace。新增收尾指南要求保留 capture-time设置，停进程后从已验证备份恢复非预期变更，先存证再清理生成文件，不覆盖用户改动。
5. **真实后端证据可能丢失。** 上轮配置 Forward+，实际回退 Compatibility/llvmpipe。Godot 指南要求从实际运行日志判断后端，记录无法验证项。对支持的新 gdx `capture record --logs-dir` 先探测help再使用；旧版不会盲传参数，独立探针需明确标注。
6. **请求分辨率不等于实际视频尺寸。** gdx迭代实测请求320×240而编码为1280×720。指南新增媒体尺寸/帧数/时长的实测核查，不信请求回显字段。
7. **每轮报告的完成条件。** 已有0.1.1自动HTML/Markdown机制保留，skill进一步要求完整真实观察、可打开附件、已核验的原始证据、明确旧错/未验证/回退。绕过CLI的工作生成独立报告，不伪造run manifest。
